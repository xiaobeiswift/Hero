# 系统关窗保存失败验收

源码：`bcad06c78a229fac17c8cba4efdbf8d88a66b496`。完整无头回归已通过；这里另外使用真实Linux桌面窗口管理器的标题栏X与全局Alt+F4，未直接调用通知处理器，未修改游戏内存。原始进程结果、保存内容、操作记录、运行时摘要与日志见 `native_window_close.json`。

三个全新隔离配置分别覆盖：

- 写入失败、返回、再次关窗及恢复写入后重试。正常接下芦岸寻药任务后关窗，页面明确保留游戏；恢复目标路径后选择重试，退出码0且实际文件保存任务阶段1。
- 写入失败、明确放弃的二次确认、取消放弃，以及重新确认后退出。取消时窗口仍在；确认后退出码0，没有写入存档。
- 正常关窗。普通按键使位置由(460,430)移动至(465.396,430)，Alt+F4后退出码0，文件写入新位置。

失败由本次测试拥有的空目录占住 `user://hero_save.json` 引起，触发真实原子重命名失败。只将该合成目录改名便恢复写入；没有更改权限、删除玩家存档或使用真实磁盘耗尽。所有会话已结束。221–222为游戏F12产生的实际1180×737画面，已查看，分别是失败页和二次确认页。

环境为Godot4.6.3官方编辑器运行源码、X11、OpenGL Compatibility、Mesa llvmpipe和Dummy音频。日志仅有既有VSync设置不支持提示。这里不证明Windows/macOS行为、音频听感或新的独立PCK；原0.0.16下载仍需要使用游戏内安全离开流程。

## 手动复现

1. 建立全新测试目录，以它的子目录分别设置XDG_DATA_HOME、XDG_CONFIG_HOME、XDG_CACHE_HOME。不得使用个人默认配置。
2. 失败情形下，在数据目录内建立 `godot/app_userdata/Hero · 渡灯录/hero_save.json` 空目录。正常情形不建立该目录。
3. 以这些环境变量启动 `godot --path . --audio-driver Dummy`，正常进入游戏，接下开篇任务。
4. 点击实际桌面标题栏X或使用系统Alt+F4。检查失败页、返回、放弃及取消。
5. 重试情形仅将测试拥有的空阻塞目录改名保留，再选择重试保存；检查退出码与实际JSON内容。每个情形使用另一个全新测试目录。
